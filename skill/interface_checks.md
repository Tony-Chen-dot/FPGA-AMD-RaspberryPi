# 双板推理接口检查

## 适用场景

Linux 主机上传图片到 FPGA/SoC 推理服务，再将结果交给本地看板或执行器。

## 操作方法

1. 单独查询推理板健康接口，核对后端与模型；本项目为 Zynq 的 `GET /health`。
2. 用固定图片检查 `POST /predict`，multipart 字段为 `image_file`；JPEG 与原始 RGB 的内容类型须与服务支持一致。
3. 对照类别表、分数阈值和坐标所在的图片尺寸，检查客户端解析；本项目测试为 `tests/vision_tests/test_defect_labels.py` 和 `tests/integration_tests/test_pipeline.py`。
4. 将同一张图片和同一条结构化结果提交到看板 `POST /api/device/ingest`，检查时间戳、产线编号与图片地址。
5. 最后连接控制器，比较预期 OK/NG 与动作方向，单独记录动作完成时间。

## 失效条件

模型类别、预处理尺寸、坐标格式、上传字段、数值精度或控制协议变化时，应先更新契约与测试输入。原始 RGB 需要双端同时支持；JPEG 请求成功不等于原始流请求成功。

## 验证效果

现有测试检查 JPEG/RGB 内容类型、阈值与胜出类别、原图预览、任务队列和多产线数据隔离；实测结果见验证记录。执行器成功率与端到端时延待补充上板测试。
